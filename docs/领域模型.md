# 文化项目组合治理 · 领域模型

面向省文化主管部门落实文化产业“十五五”规划的项目组合治理服务。本文档说明聚合、事件、
不变量、看板下钻、访问边界与公开口径，是 `src/` 各模块的语义依据。

## 1. 设计原则（沿用仓库既有约定）

1. **事件即事实，只追加不改写**：事件一经接收，`event_id`、`occurred_at`、`version` 不得原地变更；
   更正、更名、调整一律产生后继事件（同聚合流上更高 `version`）。
2. **流版本连续**：每个聚合实例的 `version` 从 1 开始严格 +1、不得跳号，后继事件时间不得早于前驱。
3. **向后兼容扩展**：基础信封 7 个必填字段（`event_id / event_type / aggregate_type / aggregate_id /
   occurred_at / version / summary`）保持不变；本次仅新增枚举值与可选追溯字段
   （`actor_id / actor_role / causation_id / idempotency_key / payload`）。
4. **最小知情**：个人、机构与商业敏感字段仅向完成职责所必需的角色开放（见第 6 节）。

## 2. 聚合与事件目录

| 聚合 | 含义 | 关键事件 |
| --- | --- | --- |
| `policy_goal` | 规划目标与年度指标，承载政策更名与目标调整 | `POLICY_GOAL_DEFINED` `TARGET_SET` `TARGET_ADJUSTED` `POLICY_RENAMED` |
| `funding_stream` | 四个专项资金（科技融合/县域消费/文旅协同/海外发行） | `FUNDING_STREAM_OPENED` `FUNDING_STREAM_RENAMED` |
| `assessment_period` | 年度考核期，可锁定 | `ASSESSMENT_PERIOD_OPENED` `ASSESSMENT_PERIOD_LOCKED` |
| `outcome_measure` | 指标与成果去重账 | `METRIC_DEFINED` `OUTCOME_DEDUPLICATED` |
| `applicant_subject` | 申报主体与最终控制集团穿透 | `SUBJECT_REGISTERED` `CONTROL_RELATION_DECLARED` |
| `funding_application` | 申报、冲突、补正、评审派单、撤回 | `APPLICATION_RECEIVED` `CONFLICT_DECLARED` `REVIEW_TASK_ASSIGNED` `APPLICATION_AMENDED` `APPLICATION_DUPLICATE_REJECTED` `APPLICATION_WITHDRAWN` |
| `funded_project` | 立项、里程碑、合同执行、追回 | `FUNDING_APPROVED` `MILESTONE_VERIFIED` `BUDGET_TRANSFER_REQUESTED` `MILESTONE_DELAY_REQUESTED` `PROJECT_TERMINATION_REQUESTED` `FUNDS_RECOVERED` |
| `decision_record` | 行政决定链（回避/调剂/延期/终止/追回） | `RECUSAL_DECIDED` `BUDGET_TRANSFER_DECIDED` `MILESTONE_DELAY_DECIDED` `PROJECT_TERMINATION_DECIDED` `FUNDS_RECOVERY_DECIDED` |
| `contract_payment` | 合同备案、支付请求、拨付/阻断 | `CONTRACT_RECORDED` `PAYMENT_REQUESTED` `PAYMENT_EXECUTED` `PAYMENT_BLOCKED` |
| `evidence_pack` | 成果证据材料包与指纹去重 | `EVIDENCE_SUBMITTED` `EVIDENCE_DEDUPLICATED` |

完整枚举以 `contracts/domain.schema.json` 与 `src/catalog.js` 为准。

### payload 关键字段约定

- 申报 `APPLICATION_RECEIVED.payload`：`stream_id / goal_id / period_id / lead_subject_id /
  co_subject_ids / budget_requested_wan / regions / metric_contributions / expense_items[]`。
  其中 `expense_items[].item_key` 是规范化支出键，用于识别跨专项拆单。
- 立项 `FUNDING_APPROVED.payload`：`application_id / approved_wan / regions / milestone_schedule[]`。
- 证据 `EVIDENCE_SUBMITTED.payload`：`files[].fingerprint`（材料指纹）、`result_claims[]`
  （`metric_id + result_key + contribution_value`）、`benefit_regions[]` 与可选 `region_shares[]`。
- 决定：挂在独立的 `decision_record` 聚合上，`causation_id` 指向上游申请事件；支付的
  `PAYMENT_EXECUTED/BLOCKED.payload.request_event_id` 指向支付请求。

## 3. 核心治理规则（`src/invariants.js`）

校验输出 `findings`：`error` 为硬性违规，`warning` 为看板可信度提示。

| 规则码 | 业务含义 |
| --- | --- |
| `SPLIT_EXPENSE` | 同一最终控制集团、同一考核期、同一 `item_key` 的支出出现在多个专项资金且申报未退出 → 重复资金 |
| `DUPLICATE_APPLICATION` / `DOUBLE_PAYMENT` | 同一 `idempotency_key` 不得二次受理、二次拨付 |
| `TARGET_ADJUSTED_AFTER_LOCK` | 跨年度目标调整只作用于尚未锁定的考核期；锁定后的调整一律拒绝 |
| `DECISION_UNAUTHORIZED` | 回避/调剂/延期/终止/追回只能由对应行政角色作出（企业只能申请） |
| `DECISION_CAUSATION_INVALID` | 每个决定必须有合法上游（如调剂决定←调剂申请，追回执行←追回决定） |
| `REVIEW_CONFLICT_NOT_RECUSED` | 评审专家与申报主体同属一个控制集团且未回避，不得立项 |
| `BUDGET_TRANSFER_NEEDS_FINANCE` | 累计调剂超批准额 20% 须财务处共同决定；调剂总额不得超批准额 |
| `PAYMENT_ON_LATE_EVIDENCE` | 里程碑材料迟报且无在先延期批准，不得拨付（系统应发 `PAYMENT_BLOCKED`） |
| `PAYMENT_ON_DUPLICATE_EVIDENCE` | 指纹重复的材料只认首包，重复件不得作为拨付依据 |
| `PAYMENT_AFTER_TERMINATION` | 终止决定后不得再发生拨付 |
| `RECOVERY_WITHOUT_DECISION` / `RECOVERY_OVER_DECIDED` | 追回执行须有前置决定且不超额 |
| `OUTCOME_DOUBLE_COUNTED` | 多个项目对同一 `metric_id|result_key` 计绩 → 同一成果被重复计算，须 `OUTCOME_DEDUPLICATED` |
| `STREAM_VERSION_GAP` / `STREAM_TIME_REVERSED` / `AGGREGATE_MISMATCH` | 流版本、时间序、挂载聚合的契约校验 |
| `MILESTONE_OVERDUE` / `NO_BENEFIT_REGION` | 逾期未核验、未登记受益区域等预警 |

**共同贡献 vs 重复计算**：多个项目可以共同贡献同一个指标（如县域消费季同时计入
`M-COUNTY-01` 与 `M-TOUR-01`）；但同一个成果（同一 `result_key`，如同一场活动场次、
同一软著登记号、同一海外发行备案）在同一指标上只计一次。

**更名不抹口径**：`POLICY_RENAMED` / `FUNDING_STREAM_RENAMED` 只更新 `current_name`，
`original_name` 与 `original_approval_no` 永久保留，看板与考核继续携带原批复文号。

## 4. 决定链（有权限、可追溯）

```
企业/县级发起 *_REQUESTED ──causation_id──▶ 行政角色 *_DECIDED（decision_record）
FUNDING_APPROVED 须由 APPLICATION_RECEIVED 引起；评审冲突先 RECUSAL_DECIDED 再改派
PROJECT_TERMINATION_DECIDED ──▶ FUNDS_RECOVERY_DECIDED（财务处）──▶ FUNDS_RECOVERED（入库）
PAYMENT_REQUESTED ──▶ PAYMENT_EXECUTED 或 PAYMENT_BLOCKED（携带阻断原因，反馈给企业）
```

角色权限矩阵见 `src/catalog.js` 的 `DECISION_AUTHORITY` 与 `DECISION_CAUSATION`。

## 5. 看板读模型与逐级下钻（`src/read-models.js`）

每个数值单元格都带 `trace`，支持「省级汇总 → 核验材料」逐层下钻：

1. **资金集中 `fundingConcentration`**：专项 × 考核期 → 按最终控制集团穿透的份额
   （默认 30% 预警）→ 集团下钻到项目 → 项目下钻到申报、合同支付、证据与原始事件链。
2. **城乡缺口 `urbanRuralGap`**：指标 × 考核期的目标值/完成值/缺口，按城市与县域拆分；
   完成值来自「去重后成果 × 区域受益份额」，未申报受益区域进入 `unclassified` 预警；
   行内保留 `original_approval_no`，政策更名不影响考核口径。
3. **里程碑风险 `milestoneRisks`**：`overdue / due_soon / on_track / verified` 分级，
   已批准延期更新到期日并挂接延期决定；已终止项目不参与风险统计。

溯源链结构：`goal_id → application_id → project_id → payment 请求/拨付 → evidence_id →
event_ids[]`。`resolveTrace()` 可把引用解析为完整材料，再经访问过滤输出。

## 6. 访问范围（`src/access.js`）

- **APPLICANT 企业**：仅见自身（含同控制集团成员与联合申报参与方）的申报、项目、材料与反馈；
  企业桌面 `applicantDesk()` 提供受理/补正/重复拒收/行政决定/支付阻断原因时间线；
  回避反馈仅告知「已按规定启动评审回避」，不披露评审专家身份；输出剥离 `actor_id`。
- **REVIEWER 评审专家**：仅见被指派且本人未回避的申报。
- **COUNTY_OFFICER 县级**：仅见受益区域落在本辖区（区划前缀）的项目与材料。
- **省级规划/财务**：全量履职视图。
- **PUBLIC**：不经本模块，统一走公开发布口径。

## 7. 公开汇总隐私（`src/public-view.js`）

公开层只到「专项 × 年度 × 城乡类」与「指标 × 区县」，**不下钻到主体、项目、证据**，并叠加：

- **k-匿名**：单元格内至少 3 个相互独立的最终控制集团（`minSubjects`）；
- **主导份额**：任一集团份额不超过 65%（`maxDominance`），防止小样本反推；
- **舍入**：金额按 100 万元步长、数量按 5 的倍数舍入；
- **互补抑制标记**：同维兄弟格被抑制时给出 `complement_suppressed` 提示，防止用
  「合计 − 已发布格」做差分反推；
- 被抑制单元格只返回抑制原因，不携带任何金额、主体字段。

样例数据只有少量主体，公开视图会大面积抑制——这是预期行为，证明未发布商业计划无法被反推。

## 8. 样例导览（`data/sample-events.json`，E001–E095）

- E023/E024：星瀚集团经控股子公司把同一算力支出拆入科技融合与县域消费两个专项；
  E030 系统预警 `CONFLICT_DECLARED`，E031 企业撤回（解除重复）。
- E029：同幂等键重复申报被 `APPLICATION_DUPLICATE_REJECTED` 拒收，不产生二次受理。
- E032–E034：评审专家与企业同控制集团 → 回避决定 → 改派。
- E047–E050：120 万元调剂（超批准额 20%）规划处与财务处共同决定。
- E051–E056：成果核验后放款；E052/E053 重复上传材料被指纹去重，不得作为拨付依据。
- E061–E063：同路光影迟报且无延期批准 → `PAYMENT_BLOCKED`；
  E068–E073：终止 → 追回决定 → 70 万元缴回。
- E069/E071/E076：青岚与远山对同一场联合展销重复计绩，去重后只保留首核验的青岚
  （县域消费完成 320+150=470 万人次，而不是 620）。
- E090 锁定 2026 考核期；E094 对尚未锁定的 2027 期调整目标（合法）；
- E048/E093：专项与政策更名，原名与原批复文号在看板中保留。
